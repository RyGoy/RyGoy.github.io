# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Hugo static site ("The Tender For Law"): an archive of old Facebook group posts and comments (2013–2018) plus long-form articles by various authors. No theme (`themes/` is empty); all templates live in `layouts/`. Deployed to GitHub Pages.

## Architecture notes

`docs/` holds the architecture for people, as linked notes that open in Obsidian (`docs/README.md` is the map; `docs/architecture/*.md`, one per part; `docs/architecture.canvas`; `docs/changelog.md` from `scripts/docs_changelog.py`). When a change alters how a part works, update its note in the same change; add any outside service to `docs/hosting.md`.

## Beginner's guide

`guide/` is a second Obsidian vault, for learners: paths of lessons that teach the accounting lens the archive assumes, quoting only Scott Duncan's and Chris Schulte's own words (`guide/README.md`). The lessons (`guide/lens/`, front matter `terms:` and `search:`) and paths are written by hand; `scripts/guide_build.py` writes `guide/terms/` (one note per dictionary term) and `guide/sources/` (each lesson's ranked candidate quotes) and checks that every quote in a lesson appears word for word at the address it links (`check` to only check): the blockquotes, and the quotes in the running text, written with the quoted words as the link inside the quote marks, `"[his words](https://thetenderforlaw.com/…)"`. The lessons say what they mean in Scott Duncan's own words where he has them, each quote linked to where he wrote it and each term to its dictionary entry (`../terms/<id>.md`). Run it after editing a lesson or the dictionary. Lessons are drafts until someone who knows the material approves them; don't state the archive's teaching as fact in them, attribute it.

The lessons are also the site's pages: `[module]` in `config.toml` mounts `guide/lens/` as `content/accounting/lens/` (the Accounting page's third card, after Start Here and the flash cards), with `guide/lens/_index.md`, the lesson plan, as its section page (`type: lesson`, cascaded). `layouts/lesson/` renders them; `partials/lesson-content.html` drops the Markdown title and the Obsidian line under it (`[The accounting lens](_index.md) · step N of 8 · …`), since the page has its own buttons to the lessons either side, above and below (`partials/lesson-pager.html`), and turns Obsidian's callouts (`> [!warning] …`, and the folding `> [!question]- …`) into boxes (written when the deploy's Hugo 0.114 had no blockquote hook); `layouts/lesson/_markup/render-link.html` points lesson links (`02-….md`, `_index.md`) at their pages, term links (`../terms/<id>.md`) at the Dictionary, and drops links to the vault's other files. A file with `draft: true` stays off the site until approved: `hugo server -D` shows it; the deploy builds without `-D`. Publishing a lesson is setting `draft: false` (the plan's too, for the card to show).

## Settings

`config.toml` holds every setting an administrator changes, one `[params.<feature>]` section per feature (`telegram`, `live_sign`, `animation_links`, `webamp_dock`, `comments_app`, `link_preview`, `grand_fluff_auto`), each with a comment naming the template that reads it and, for features that can be turned off, an `on` switch. Put a new switch there, not in a template variable or a commented-out block, and document it in the section's comment.

## Commands

- Dev server: `hugo server`
- Production build (mirrors CI): `hugo --minify`
- Hugo version is pinned to **0.152.2 extended** in `.github/workflows/hugo.yml` (0.114 until November 2026, when it failed some builds with `readAndProcessContent: open …/public/_index.html`). Avoid template functions newer than 0.152.2.
- No tests or linter. Verify changes by building and inspecting output. The content tree is ~126k files, so full builds are slow.

## Deployment

The site is at https://thetenderforlaw.com/ (custom domain set in the repository's Pages settings, HTTPS enforced; `rygoy.github.io` redirects there). `static/CNAME` names it, but Pages ignores the file for Actions deployments: the domain lives in the settings, and the build takes its `--baseURL` from them (`actions/configure-pages`), so `baseURL` in `config.toml` matters only for local builds. `.github/workflows/hugo.yml` builds on push to `main` (or manual dispatch) and deploys `./public` via `actions/upload-pages-artifact` / `actions/deploy-pages`. CI rebuilds `public/` from scratch. GitHub Pages' file sync usually takes 1–2 minutes, but at times a deployment stays in "syncing_files" until `actions/deploy-pages` gives up at its 10-minute maximum ("Timeout reached"; raising its `timeout` input has no effect). This is on GitHub's side: it happened at 259 MB as well as at ~800 MB, while other deploys of the same artifact took a minute. The deploy job then retries by itself: its "Retry a stalled deployment" step asks the Pages API for a new deployment of the same artifact under a new build version (up to three attempts of nine minutes), because a deployment named after the same commit never starts again. So don't re-run a failed deploy by hand; if all attempts fail, deploy a new commit (merge or push the next change).

`public/` is not kept: `.gitignore` leaves it out (with `node_modules`), and CI builds it afresh for each deploy. Every build writes about 256,000 files, which filled this machine's inodes when each worktree kept one, so build into a scratch directory (`hugo -d <dir>`) and delete it once checked, delete any `public/` once the build has been pushed, and run the preview as `hugo server --renderToMemory` (Hugo 0.123 and later otherwise render the preview to `public/`). `resources/` is still committed.

## Content model

Content is machine-exported Facebook data. Front matter is **JSON** (or TOML `+++` for articles).

- `content/vol_<roman>/` — one section per volume. `_index.md` holds `Title` ("Volume N") and `weight`.
- `content/vol_*/<post_id>/_index.md` — a **post**, as a branch bundle. Fields include `id`, `created_time`, `from_name`, `from_id`, `message`, `link`, `name`, `caption`, `description`, `source`, `type`, `place`.
- `content/vol_*/<post_id>/<post_id>-<comment_id>.md` — **comments** on that post. Fields: `id`, `post_id`, `from_name`, `message`, `created_time`.
- Volumes hold a quarter each (UTC, by `created_time`): I–XIV are 2013 Q1 to 2016 Q2 (XIV runs to 5 July 2016, where the original export ends); XV–XIX (2016 Q3, 2016 Q4, 2017 Q1, 2017 Q4, 2018 Q1) hold only posts from the later export below.
- Imported posts and comments (`"imported": "TTFL DB.db"`): `scripts/import_db.py "<TTFL DB.db>" [--dry-run]` adds the posts a later export of the group (SQLite, January 2013 to March 2018) has and `content/vol_*/` lacks, by id, with their comments, in the volume for their quarter. That export keeps less: messages have no line breaks, and there is no link title, caption, description, user ID or update time (left empty). It also has comments on posts the site already has and replies to comments (the site shows no replies); the script leaves both out. 152 posts and 3,219 comments were imported on 2026-11-12.
- `content/articles/<author>/*.md` — articles, TOML front matter (`author`, `title`, `date`, `weight`, `tags`, `categories`, and `cc_license = true` for those shared under CC BY-NC-ND 3.0, which `partials/article.html` states once, after the text; don't write the licence into the body). Author dirs are sections, ordered `ByWeight`. Raw HTML in articles is not rendered (Goldmark without `unsafe`), so pictures are Markdown images (the old Bootstrap carousels, whose `/img/` pictures never existed, were removed). A Markdown image of an `.mp4` or `.webm` plays as a video (`_default/_markup/render-image.html`). Articles first published on kentbarrett.com show that page's picture from the Wayback Machine (`static/images/articles/<article>.<ext>`, at the top, with "*Picture: [Kent Barrett](<Wayback copy of the page>)*" under it); Who's On First has no saved copy of its picture. Seven of Tara Duncan's articles and Eliminating Disease show the banner of their copy on Minds (the taraduncan and roguesupport channels' blogs, from cdn.minds.com), credited "*Picture: [Minds](<the blog>)*". Many article files have Windows line endings: keep them when editing.
- `content/{accounting,agency,bills-of-exchange,insurance,title&property}/` — subject pages, grouped as the **Library**. `content/library/_index.md` lists them in its `subjects` front matter; the sidebar Library group, the home page Library section and `/library/` (`layouts/library/list.html`) all read that list. `title&property` is published at `/titleproperty/`, with an alias from `/title&property/`.
- `content/accounting/corporateregistration/` — Corporate Registration (`/accounting/corporateregistration/`, `layouts/corporate-registration/`, the section's `type`, cascaded): one page per jurisdiction, 64 in all (federal Canada, the provinces and territories, the 50 states), each a file with JSON front matter and no body: `title`, `weight` (the order everywhere, Canada first), `country`, `region`, `flag` (`static/images/flags/<flag>.webp`, from Wikimedia Commons; federal Canada's `canada.webp` is the 1921 Red Ensign drawn from `static/images/canada-shield-1921.svg`), `office`/`office_url`, `act`/`citation`/`act_url`, `security_registry` and `security_registry_url` (UCC-1 or PPSA; the URL may be left out, as for federal Canada), the summaries `legal_system`, `minimums`, `number_names`, `tax` with their `sources` (`minimums` and `tax` are lists of short items, shown as bullets; the others are one sentence), an optional `note` shown for the reader (Quebec's on federal corporations), `notes` (not shown: what research couldn't confirm) and `articles` (`document`, `who_may_incorporate`, `items` of `section` and `text`, `url`: what the act requires the articles of incorporation to say, quoted). A missing field or flag stops the build. `_index.md` holds the introduction, the "at the time of this writing" `notice` (Markdown, shown below the cards on the section page and at the foot of every jurisdiction's page) and `countries`: their order, each with its regions in order, the `security_label` for its registry line and an optional `note` shown under its heading (Canada's on federal and provincial corporations); `list.html` shows a small linked card per jurisdiction under its country and region, and stops the build if a page's country or region isn't listed. Being a section, it lists every jurisdiction in its card on `/accounting/` (`partials/article-list.html`). Link official sites only; where a state's code is free only on LexisNexis, use its `lexisnexis.com/hottopics/<code>/` address, which opens the whole code.
- `content/library/*.md` — library books (`layouts/library/single.html`). Front matter: `author`, `edition` (not `published`, which Hugo reads as a date), `description`, `pdf` and `source` (+ optional `source_label`). A `pdf` starting with `/` is a copy in `static/library/` (public-domain works, or a work whose licence lets it be shared: Whyte's essay is CC BY-NC-ND, so its buttons stay on and its `[copyright]` section, without `coming_soon`, states the licence); a full address opens someone else's copy. `coming_soon = true` marks a book still in copyright: it shows the same Read the PDF, Download and source buttons as a public-domain book, switched off (spans, not links, class `is-off`), except a source on Open Library (`https://openlibrary.org/…`), which lends rather than shares a copy and stays a link, and a Copyright section below its text from a `[copyright]` table in the front matter (`status`, `holder`, `us`, `canada`: when it is expected to enter the public domain in each). Keep its `source` in the front matter for when the buttons are turned on. Public-domain books keep a local copy in `static/library/` (Read the PDF and Download) and the source link. Every book has a `cover`: an image in `assets/images/library/<slug>.webp` (at most 600px wide), which Hugo resizes, shown beside the summary on the book's page (360px) and as a thumbnail in the Library list (72px); `cover_alt` describes it when it isn't the cover (a title page, a frontispiece), and `cover_credit` with `cover_credit_url` credits a picture whose licence asks for it (the UCC's photo, CC BY-SA). A missing file stops the build. The in-copyright books' covers are first-edition covers from English Wikipedia, kept at its low (fair use) resolution. `emblem = "cobra"` (Ho, Canada!, The English Constitution and The Art of War) replaces the rose window with the cobra, an important symbol, so it is shown in its own colours beside the title, not as a faint emblem: `static/images/emblems/cobra-colour.webp`, a cut-out of COBRA.svg with its white background removed, lightly toned for each theme by CSS filters (a little sepia in Sepia, a glow of the emblem red in Dark). It is a real element in the heading (`.page-emblem`, from `partials/page-emblem.html`), not the `::after` the rose uses. Articles take the same `emblem` and `[emblem_video]` (`partials/article.html`): every article by Chris Schulte, and Ryan Wallace's Show Me The Money (not his other articles), plays `static/videos/trainedwell.mp4` ("Trained Well My Young Apprentice"); give a new Chris Schulte article the same block. On phones it sits under the heading. With an `[emblem_video]` table (`src`, `poster`, `title`, `width`, `height`) it is a link that plays that video in a pop-up (`#emblem-video`, styled like the blade's), stopping when the pop-up closes; without JavaScript the link opens the file. `width`/`height` also set `--video-ratio` on the pop-up, which narrows it for a tall video so it fits the screen height. Ho, Canada!'s plays `static/videos/fumbles-robot-chicken.mp4` (poster `fumbles-robot-chicken.webp`); The Art of War's plays `static/videos/must-know-violence.mp4` (portrait, poster `must-know-violence.webp`). The English Constitution's plays `static/videos/rebel-scum.mp4` (poster `rebel-scum.webp`). The body of `content/library/_index.md` is the "Reading the Bible" guide (heading from `guide_title`), rendered on `/library/` below the cards; it uses the `cards`, `card` and `callout` shortcodes in `layouts/shortcodes/`.

## Template architecture

Templates branch on the **shape of the data**, not on content type:

- `_default/list.html`: `.Params.id` set means a post bundle; render the post plus comments sorted by `created_time`. Section starting with `vol_` means a volume index (`partials/volume-list.html`, grouped by month). Otherwise it is an article list.
- `_default/single.html`: `.Params.id` set means a single comment/post page. Otherwise it is an article (`partials/article.html`).
- `partials/entry.html` renders any post or comment. It composes `lpPosts.html` (body), `lpGo.html` (comments link, posts only), and `entry-metadata.html`. A comment is recognised by `.Params.post_id`.
- `partials/volumes.html` is a **returning partial**. It sorts volume sections by the number parsed from their title, because the original `weight` values repeat. Use it (via `partialCached`) whenever volumes need ordering.
- `baseof.html` caches the navbar with `partialCached`, keyed on `.FirstSection.RelPermalink` (or `.CurrentSection` under `articles`, or the page's own address for top-level pages such as `/agency/`). Per-page state in the navbar must stay consistent with that key.

## Search

`/search/` (`content/search.md`, `layouts/_default/search.html`) runs the Pagefind UI. After `hugo`, the deploy workflow runs Pagefind twice, writing two indexes: everything outside the volume folders (articles, library, dictionary, commentary) to `public/pagefind/`, and the volumes' Facebook threads to `public/pagefind-volumes/` (`--glob 'vol_*/**/*.html' --output-subdir pagefind-volumes`). The search page merges them before starting Pagefind UI, with the threads at `indexWeight: 0.6`, so a thread that only mentions a subject doesn't outrank the writing about it; and it ranks titles at a tenth of their usual weight (`metaWeights.title: 0.1`), because a thread's title is its poster's name (an article's title is also its heading, which counts anyway). Both are indexed with `--force-language zz`, a language code Pagefind has no stemmer for, so words stay as written: every result of a search has every word as typed ("accountants" doesn't match "accounts", nor "policy" "police"; only the last word also matches as the start of a longer word, as you type). Pagefind UI loads `static/js/search/pagefind.js` (`bundlePath: js/search/`) in place of Pagefind's module: it passes everything through to `/pagefind/pagefind.js` except `search`, which, for a search of several words, also searches them as a quoted phrase and lists those pages first, then the rest. Weighting a whole page with `data-pagefind-weight` does nothing: Pagefind divides by the page's weighted length. Posters' and commenters' names (the `h2` in `partials/lpPosts.html`) count as plain text (`data-pagefind-weight="1"`), not as headings. `hugo` alone produces no index, so the search page shows "Search needs JavaScript and the search index". To try search locally, build into another directory, run both Pagefind commands from `.github/workflows/hugo.yml` with `--site <dir>`, and serve the directory.

Only elements marked `data-pagefind-body` are indexed: post bundles (the post plus its comments, in `_default/list.html`) and articles, meaning pages in `articles` and in the subject sections (`partials/article.html`). Single-comment pages and volume indexes are left out because they repeat that text. Each indexed page sets a `Section` filter (`Volumes`, `Articles` or `Commentary`). `data-pagefind-ignore` keeps the metadata and "Read Comments" labels out of the results. The sidebar search box (`partials/navbar.html`) submits `?q=` to `/search/`.

Searches can also be filtered by `Author` (who wrote a post, article or commentary note) and `Commenter` (who commented on a post). These come from `data-pagefind-filter` on the names in `partials/lpPosts.html`, `partials/article.html` and `commentary/single.html`. `Year` (posts, articles, notes) and `Volume` (posts) come from empty elements written by `partials/search-filters.html`: one `data-pagefind-filter` attribute holds only one filter, and the values are plain numbers so the search page lists them in numeric order.

The search page shows the filters as searchable dropdowns, not Pagefind UI's checkboxes (`static/js/search-filters.js`): one text box per filter, under the search box, whose list (a `<datalist>` of the values in the index, from `pagefind.filters()`) narrows as you type; a chosen value becomes a removable tag, and the selection reaches the results through `PagefindUI.triggerFilters`, so it combines as the checkboxes did. Pagefind's checkbox panel is hidden only once the dropdowns are in place. They sit inside Pagefind's form, whose stylesheet resets everything there (`all: unset`) at one class's weight and loads after `archive.css`, so their rules (and the box and tag styles they share with the poster filter) carry a second selector.

## Search engines

- Titles and descriptions: `partials/seo-meta.html` (from `partials/head.html`). Posts and comments are titled "the opening of the message – Author · The Tender For Law": the words first, because a search result shows only about 60 characters, with web addresses left out and the opening shortened to keep the title near 80; a short message (under 25 characters, such as ":)") adds its date, and one with no message is named by its link's title or as "Picture/Post/Comment, date and time". They are described by the message's opening (`partials/seo-text.html`, the message as one line of plain text), with who wrote it and when if it is under 70 characters; their front matter's `description` is the shared link's, so a post with no message is described by who shared it, when, the link's title and its first comment. The home page is titled with what the site is. Volumes are described by their months and number of posts; other pages use their own description, or the opening of their text (without the licence line that opens many articles), or, for lists such as tag pages, how many pages they list and the first few, or else the site's (`params.description` in `config.toml`). Give a new article its own `description`: articles open with a picture credit or a notice, which make poor descriptions.
- Markdown render hooks (`layouts/_default/_markup/`): `render-image.html` gives a picture kept in `static/` its width and height (`imageConfig`), so the page doesn't jump as it loads; Go reads only common JPEG subsamplings, so a JPEG that fails the build with "unsupported JPEG feature" must be saved again (`convert in.jpg -sampling-factor 4:2:0 out.jpg`). `render-heading.html` writes a `# heading` in the text as an `h2` (class `h1-size`, styled like `.prose h1`), so each page has one `h1`, its title.
- Every page names its address (`<link rel="canonical">`). Single-comment pages (126,000 of the site's 130,000 pages, each repeating its post's page) and the 404 page are `noindex, follow`, and the sitemap leaves comment pages out (`layouts/_default/sitemap.xml`): with them it passed the 50,000 addresses a sitemap may hold. `robots.txt` (`layouts/robots.txt`, `enableRobotsTXT` in `config.toml`) names the sitemap. The sitemap's last-modified date is a post's last activity (`updated_time`, else `created_time`), a volume's newest post's, or another page's own `lastmod`/date.
- Every article has its own `description` (the search result's text); give a new article one.
- Posts and comments that became articles say "Also published as an article" with a link (`partials/lpPosts.html`), so search engines take the article as the main copy. The list is read from the articles' opening line (`*First posted to …`, `*First appeared …`, `*Posted to …`, `*Shared to …`, linking `/vol_x/<post id>/` or `…/#entry-<comment id>`) by `partials/article-sources.html` (a returning partial, via `partialCached`), so a new article made from a post needs only that line.
- Structured data (schema.org JSON-LD, `partials/structured-data.html`): the home page is a WebSite; posts are DiscussionForumPostings with their comments and recovered pictures (a post with no text but a picture is one too, headed "Picture shared by …"); articles (the articles section and the Library's subject sections) are Articles, with their first Markdown picture or else the site's card, and ROGUESUPPORT INC as publisher (an Organization with its logo, `static/images/roguesupport-logo.jpg`), also as author when the byline is ROGUESUPPORT INC; no `dateModified` (articles have no reliable edit date); every page but the home page, comments and the 404 has a BreadcrumbList.
- The templates must build with Hugo 0.152.2 (CI). Moving to a newer Hugo can change URLs: 0.152 urlizes the category "MAN ≠ PERSON" as `man--person`, where 0.114 made it `man-person`, so `content/categories/man-≠-person/_index.md` keeps the old URL. Compare the sitemap before and after any upgrade.
- IndexNow (Bing, Yandex and others; not Google): after each deploy, the workflow's `indexnow` job sends the sitemap addresses whose page changed, appeared or went away to api.indexnow.org (`scripts/indexnow.py`, standard library Python). The build job finds them by comparing a SHA-256 of each sitemap page's HTML with the fingerprints last sent, kept in the Actions cache (`indexnow-manifest.json`, saved only once the addresses are accepted, so a failed send is retried by the next deploy). With no fingerprints (the first run, or the cache unused for 7 days and evicted) it sends every address (about 3,900), in one request (the limit is 10,000). The key is `static/indexnow.txt`, served at `/indexnow.txt`; the script reads it from the live site, so the key file and the request always agree. It is public by design; to change it, replace the file. Google doesn't use IndexNow: it needs the sitemap submitted in Search Console.

## Most Discussed

`/most-discussed/` (`content/most-discussed/_index.md`, `layouts/most-discussed/list.html`) shows the 100 posts with the most comments, from all volumes. `partials/volumes.html` appends it after the last volume, so the sidebar, the home page and the previous/next links treat it as a volume. Its `symbol` (✝) and `number` (∞) front matter stand in for the roman numeral and the volume number. The page is laid out like a volume page: the same header, with places in tens (Places 1–10 …) for months, and the poster filter hides empty sections. Its heading emblem is a crucifix (`static/images/emblems/crucifix.svg`, `.discussed-heading`) in place of the rose window used on every other page.

## Dictionary, concordance and inline definitions

`/dictionary/` (`content/dictionary.md`, `layouts/_default/dictionary.html`) lists the terms in `data/dictionary.json`, every definition shown. Definitions are in the archive's own words; ones that quote a statute, dictionary or other writer are left out. The exception is kind `wex`: for terms the archive does not define, the opening paragraph of the term's entry in Wex, the legal dictionary of Cornell Law School's Legal Information Institute (shared under CC BY-NC-SA 2.5), credited and linked, with its `license` ({name, url}). These are light blue on the page and in the inline cards, and a note under the page heading says so. A definition by someone other than Scott Duncan gives the writer in `by` (Chris Schulte on Accounting), shown before its source. A term can have an empty `definitions` list: it is listed as "No definition yet", is in the concordance, and is linked inline with a card that says so. The terms written in capitals in Scott Duncan's and ROGUESUPPORT INC's articles were added this way when his posts and comments in the volumes had no definition of them. An entry's optional `match` list gives the words to look for when the term is not itself one (`Include, Including`); an empty list leaves it out of the next two features. An entry's optional `forms` list gives other written forms (`ACCEPTED, ACCEPTING` for Acceptance; `LEGALLY` for Legal) that are linked inline as the term; they are not counted in the concordance, which keeps its output (and the deploy's file count) down.

- **Concordance**: `scripts/concordance.py` (standard library Python) finds every use of each term in posts, comments and articles (whole word, any case) and writes `public/concordance/index.json` and `<id>/<n>.json` chunks of 500. The deploy workflow runs it after Pagefind; a plain `hugo` build has no concordance, and `/concordance/` (`layouts/_default/concordance.html`) says so. To try it locally, run the script with a build directory's `concordance/` as the argument. The output is about 55 MB.
- **Inline definitions**: `static/js/dictionary-terms.js` links the first use of each term written in capitals (or its plural, unless that is a term of its own) in each post, comment and article to its entry, with its first definitions (up to three, numbered, each with its source) in a card on hover or focus. Its terms come from `/dictionary-terms.json`, built by `partials/dictionary-terms.html`.
- **The "accountants set policy" video**: `static/js/video-links.js` (loaded just before `dictionary-terms.js`, which then skips its links) links every mention of Steve Paikin or The Agenda (and theagenda.tvo.org), "bookkeepers make the rule(s)", and accountants setting (public) policy in posts, comments and articles to `static/videos/accountants-set-policy.mp4` (62 MB, kept at full quality on purpose). 22 links when added (November 2026).

## YouTube videos in posts and comments

A post or comment whose message links a YouTube video (`youtube.com/watch?v=`, `youtu.be/`, `embed/`, `shorts/`, mobile links), or a post whose link is one, shows each video under its text and above the link card (`partials/youtube-embeds.html`, called from `partials/lpPosts.html`). Message text is front matter, where shortcodes don't run, so the template finds the links itself. Each video is a thumbnail until clicked; `static/js/youtube-embed.js` then swaps in the youtube-nocookie player, so pages with dozens of videos load none up front. Without JavaScript the thumbnail links to YouTube. Removed videos show YouTube's grey placeholder.

In articles and other Markdown pages, a YouTube video is embedded with Hugo's built-in `{{< youtube ID >}}` shortcode on its own line, not left as a bare address (an address inside a sentence keeps its link, with the shortcode after that paragraph).

## Archived links

Posts and comments show archived copies of their outside links: under a post's link card, and in a list under a message, each labelled "Archived link (<archive>, saved <date>)" with a note that it was added by this site and is not part of the original. The record is never changed: messages and original links render exactly as exported (apart from the added elements, a build is byte-identical to one without this feature).

- `scripts/archive_links.py` (standard library Python) reads the addresses from `content/vol_*/` and asks the Wayback Machine (CDX search, captures saved with status 200 only) and archive.today (Memento TimeMap at archive.ph) for the copy closest to the post's or comment's date. It writes every answer to `scripts/archive-checks.json` (so a run can be stopped and continued) and the confirmed copies to `data/archives.json`, keyed by post or comment ID. It is run by hand, not at deploy: it asks slowly and takes hours, and archive.today refuses many automated clients. Failed checks (errors, refusals, CAPTCHAs) are asked again on the next run and show nothing meanwhile.
- `partials/archive-links.html` (called from `partials/lpPosts.html`) shows only what `data/archives.json` lists; it finds no addresses itself. An address with no confirmed copy shows nothing.
- Left out of the check: Facebook (the Wayback Machine's copies are its log-in or security check page, saved with status 200), YouTube links in comments (shown as video thumbnails), addresses that are already archive copies, and addresses written with "..." or "…" (possibly shortened for display, so the address may name a different page). Of an address written with a final full stop, the reading with the stop is tried first, then the one without.
- The Wayback Machine refuses to search some sites (such as Dropbox, "excluded from the Wayback Machine"); the script records those as having no copy after checking that the Wayback Machine answers other searches.
- Archived links are kept out of the search index (`data-pagefind-ignore`).

- `data/anthology/v<N>.json`: `printed` (the print date, shown in every caption), `entries` (site id → picture, PDF page, printed name; `missing` and the printed `text` when the export has no name or no content), `recovered` (post id → comments the export lacks: picture, printed name, time in UTC, text, complete `links`), and the volume's title and Box address.

- Templates: `partials/anthology-entry.html` looks an id up. `partials/anthology-copy.html` (from `entry.html`) folds the picture under "Printed copy · Anthology Volume N, page P", or shows it in place of a name or content the export lacks. `partials/anthology-comments.html` merges recovered comments into a post's comments by time (the post page and the comments link both count it); `partials/anthology-comment.html` renders one. `partials/anthology-links.html` lists printed addresses (YouTube ones as thumbnails).
- Names that come only from the printout (recovered posts and comments, names the export lacks) are shown in the dictionary's Wex blue (`.anthology-name`). The exported record itself is not edited.
- Renamed members: `data/anthology_aliases.json` (printed name → export name, written by `scripts/anthology/aliases.py <repo>` after the builds; it lists the names it rejected, for review; its `KNOWN` holds renames printed once with no word in common, checked by hand) drives `partials/anthology-names.html`. A post or comment by a member renamed by the time of the printout shows both names, the export's then the printed one in blue; a recovered one shows the account's export name, then its printed name in blue. Search filters and the poster filter use the export name, so a member's posts and comments stay together under one name. `build.py` also reads it: a recovered comment that is a site comment still without a copy (same member, same post, within three minutes, same text or no letters in either; with the same text also within three hours of an estimated time, or up to two days before an edit time) is given to that comment instead.
- Page breaks: when a break swallowed one comment's end and the next one's start, `build.py` cuts the printed item in two where the second begins (its name line if printed, else the break), so each has its own picture: `cut` `end` on the first, `start` on the second (unless its name is printed). It knows such an item when the matcher linked both comments to it, when the name at its top is another member's, or by its date: the date line is the last comment's, so an item spanning a break whose printed minute isn't its comment's, while exactly one comment on the post written in that minute has no item, is that comment's end after the break (not for "Edited" or relative dates). Which of two linked comments is above the break goes by the date line, then by the name at the top, then by their texts. A second comment whose name line is hidden under the page's menu bar (or lost) still has its avatar beside its first line at the page top; the item is cut there when the text after it ends a comment written in the printed minute that has no item. A name read as a commenter's must have an avatar beside it (a name opening a line without one is a mention). `cut` `start` also marks an item that opens at a page top with no avatar (its name line fell into the break). `cut` `date` is a comment of which only the date line was printed. The caption says which (`partials/anthology-cut.html`). The few items that hold two comments' starts can't be cut and stay shared (`partial`).
- Pipeline (`scripts/anthology/`, Python with Pillow, plus poppler's `pdftotext`/`pdftoppm`): `pdftotext -bbox-layout vol.pdf bbox.html`; `pdftoppm -r 110 -png vol.pdf pages/p` (pages are `pages/p-NNNN.png`, four digits); `parse.py bbox.html parsed.json [<last header page>]` (splits the feed column into posts and comments with their page strips; a post headed after `<last header page>` belongs to the next volume); `match.py <repo> parsed.json matched.json pages` (matches by time, name and text; names are read by their blue colour; it ignores `anthology-*` posts, so a re-run needs no clean-up first); `build.py <repo> <N> matched.json pages [<last page>[:<first borrowed page>]|-] [<printed date>]`; `aliases.py <repo>` after building every volume (then build again, since `build.py` uses the renames); `verify.py <repo> <build dir> <N>` after a Hugo build; `audit.py <repo> <N> raw.txt parsed.json out.txt` (`raw.txt` from plain `pdftotext`) lists site posts and comments with no copy whose text is in the PDF, and recovered items that duplicate the site. Its leftovers are mostly false alarms: quotes, YouTube addresses, comments dated after the printout, and threads printed in another volume.
- Joins between volumes. The printout runs newest first, so a post headed on the last page of volume N continues at the start of volume N-1. Every post belongs to the volume where its header is printed: that volume gets the continuation pages appended to its `bbox.html` and `pages/` (as pages count+1…), passes `build.py` its real last page (and the first borrowed page when it isn't 1), and items on borrowed pages are labelled with their own volume (`volume` in the entry). The other volume's parser skips the opening fragment (it has no header). Because of the separate print runs, find joins by content: v2 + v1 p1; v3's last page is v2's first (the FEATURE! post stays in v2); v4's last page is v3's first (nothing appended); v5 + v4 p1; v6's last post is printed whole in v5 (kept in v5 only); v7/v6 no overlap; v8 + v7 pp2–6 (v7 p1 is v8's last page); v9's last page is v8's first (kept in v8). Parse arguments used: v2 1226, v3 1407, v5 1436, v6 1290, v8 765, v9 1520; build: v2 1226, v5 1436, v8 765:2, others `-`; printed 2014-06-14 for v1–v2, 2014-06-13 for v3–v9.
- Printout quirks the scripts handle: times are US Eastern (with daylight saving); an edited comment shows its edit time; long posts are cut short ("See More"); many members were renamed between the export and the printout ("Harry Wombat"/"Harry Nosed Wombat", "August le Blanc"/"Bobis Youruncle", "Anibal Jose Baez"/"Mackximus Minimus"; `match.py` learns such aliases from agreeing comments); 2014 dates have no year, and the newest are relative ("11 hrs", "Yesterday at"), counted back from the footer's print time (their recovered times are estimates, `time_approx`); emoticons print as pictures; members pasted other threads, date lines included, into comments (kept as one comment); Facebook exported photos, files and shares as empty posts (matched by poster and day, in print order, newest first; an upload whose header fell into a page break, between two of the same poster's that day, counts as theirs; renamed posters by `data/anthology_aliases.json`; an album post, "X added photos to …", printed with comments the export lost, pairs with its poster's one empty post that day before the first comment); every page break can drop a strip of content, including name or date lines, which no crop can recover. The parser keeps a post whose name and date fell into a page break (matched by its text and its comments' times), and a comment whose date fell into one (matched by text). When a break swallows one comment's end and the next one's start, the one printed item holds both; `build.py` cuts it in two (above).

Older students' notes connecting posts and articles. Every outside service the site uses (Cloudflare and others), and how to move the bot between hosts, is in `docs/hosting.md`: keep it up to date when a service is added, moved or dropped. "Add commentary" (`partials/commentary-add-link.html`) opens the bot on the page (`[params.telegram]` `bot`). The page travels in the start parameter (64 characters of A-Z a-z 0-9 _ -) as its lowercase path with `/` written `S` and the group ID prefix `462493170453287_` written `G`; `decodePage` in `bot.js` reverses it, so change both together. A contributor sends a title line and the note; the bot posts the file it will commit to the moderators' group with Approve/Reject, and Approve commits `content/commentary/<slug>-<message id>.md` to `main` through the GitHub API. - Notes are searchable with the `Commentary` filter. `partials/page-label.html` gives posts and comments their "Volume N · Author · date" name, shared by search titles and commentary links.
